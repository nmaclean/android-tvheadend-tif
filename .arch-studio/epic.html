4. Risks, Cut-Lines & Handoff to Gate 06

Sequencing Risks & Cut-Lines

Risk / Cut-Line Area Type Impact on Rollout Mitigation / Deferral Option
Dual TIF Services (HTSP + IPTV) Architectural Risk Shared repositories, observers, or TIF content providers could conflict across Tvheadend and IPTV inputs. Sequence E1 first, isolate IPTV data/sync paths in E4, and resolve cross-input findings in E5 before broad release.
Legacy + Compose UI Coexistence UI / State Risk Fragment/XML views and newer Compose screens (ui/screens/*, ui/settings/*) may duplicate state or navigation flows. Cut-line non-essential UI polish behind core playback and setup; consolidate screen ownership in E3 and .arch-studio/mockup-lld.html.
LAN Curation Server & External Feeds Scope / Cut-Line LanCurationServer.kt, M3U/XMLTV ingestion, and logo/EPG workers add network and parsing surface area. Treat E4 as an independent feature slice that can be deferred or feature-flagged if core HTSP/TIF playback needs stabilization first.
Split-App Feasibility vs. Monolith Boundary Cut-Line Splitting apps later carries higher packaging/IPC/auth cost if boundaries are not checked early. Use docs/SPLIT-APPS-FEASIBILITY.md and docs/boundary-contract-audit.md in E5 to lock module boundaries before major refactoring.
Uninspected Studio & Doc Specs Epistemic Gap Existing plans in .arch-studio/epic-breakdown.html, tasks.md, and AGENTS.md may already define conventions or priorities. Read those files directly at the start of Gate 06 to reconcile any pre-existing epic breakdown or agent rules.
