3. Interfaces, Data Flows & Architectural Decisions

Interface Contract

Android TIF & Channel Sync

TvheadendInputService and IptvTvInputService (declared via res/xml/tv_input.xml and res/xml/iptv_tv_input.xml) interact with TifChannelObserver, TifAllowlistSyncer, and InputChannelRepository.

Interface Contract

HTSP & Media Extraction

Htsmsg, HtspClient, HtspConnectionPool, and HtspConnectionState feed HtspDataSource, HtspDvrDataSource, HtspExtractor, and Mp2Decoder, paired with DisplayFrameRateController / FrameRateMatcher.

Interface Contract

IPTV Allowlist, EPG & LAN Curation

AllowlistRepository, IptvEpgSettingsStore, IptvLogoManager, and LanCurationServer (assets/curation/index.html) bridge LAN curation edits with IptvStreamResolver and TIF allowlist sync.

Data Flow

HTSP Sync & Live/DVR Playback

TvhSyncManager / TvhSyncWorker / SyncService populate EpgRepository, DvrRepository, and ChannelRegistry; TvPlayerActivity / DvrPlayerActivity stream media and record TuneTelemetryTracker metrics.

Data Flow

M3U / XMLTV Scan & EPG Ingestion

InputSourceHandler, SourceScanManager, and IptvStreamScanner ingest streams via StreamingM3uParser while IptvEpgSyncer and IptvEpgSyncWorker parse guide feeds via StreamingXmltvParser.

Data Flow

GitHub Release Check & APK Install

GitHubUpdateManager and SemVerComparator evaluate releases, UpdatePromptDialog presents prompts, and ApkInstaller / UpdateInstallReceiver stage updates via res/xml/file_paths.xml.

ADR-01 · Framing

Streaming Parsers & Worker Sync

Use streaming parsers (StreamingM3uParser, StreamingXmltvParser) and scheduled/background sync (TvhSyncWorker, IptvEpgSyncWorker, BackgroundSyncStrategy) to keep large playlists/guides off the UI thread.

ADR-02 · Framing

Dedicated AFR & MP2 Media Modules

Isolate display refresh-rate matching in player/afr/ and custom extraction/MP2 decoding in player/ so TV playback behavior can evolve independently from UI screens.

ADR-03 · Open Audit

Cross-Input & Split-App Boundaries

Keep Tvheadend and IPTV input responsibilities explicitly bounded pending reconciliation of docs/TIF-CROSS-INPUT-AUDIT.md, docs/boundary-contract-audit.md, and docs/SPLIT-APPS-FEASIBILITY.md.

4. Resilience, Security & Operational Guardrails

Resilience, Threading & Lifecycle

  • Connection State & Pooling: Model HTSP reconnects and session states through HtspConnectionPool and HtspConnectionState rather than blocking UI/TIF threads.
  • Service & Activity Lifecycle: Coordinate TvPlayerActivity / DvrPlayerActivity, DisplayFrameRateController, and TIF services so stream tears-downs and refresh-rate changes do not leak resources.
  • Bounded Feed Processing: Keep M3U/XMLTV parsing and EPG/DVR sync incremental to avoid memory spikes on large channel/guide sets.

Security, Privacy & Operations

  • LAN Curation Exposure: LanCurationServer serves browser curation on the LAN—verify network binding, session/access controls, and server start/stop lifecycle.
  • Credentials & APK Updates: Protect account/sync credentials (TvhAccountService, settings stores) and restrict APK file sharing via res/xml/file_paths.xml and ApkInstaller.
  • Unit Test Baseline: Maintain and run the 30 unit tests under app/src/test/ alongside .github/workflows/release.yml.
