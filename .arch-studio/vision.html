1. Executive Vision & Core Outcomes

North-Star Goal: Deliver a cohesive, TV-first Android TV Input Framework experience that unifies live television, electronic program guide (EPG) data, and DVR recordings from a Tvheadend backend alongside curated M3U/XMLTV IPTV sources, adaptive display refresh-rate matching, and browser-based LAN curation.

Target Users

Android TV / Google TV households operating a Tvheadend server and/or local IPTV/XMLTV streams who want native TV guide/channel integration, smooth playback, and effortless setup without typing long URLs or playlists on a TV remote.

Maintainers and contributors evolving TIF channel/EPG sync, HTSP extraction/decoding, IPTV parsing/allowlisting, and automated release workflows.

Measurable Outcomes (Framing)

  • Live & DVR Playback Reliability: Tune and play streams via TvheadendInputService, IptvTvInputService, HtspDataSource, HtspDvrDataSource, HtspExtractor, and Mp2Decoder, tracked by TuneTelemetryTracker.
  • Sync & Guide Consistency: Keep TIF channels, guide entries, DVR records, and IPTV allowlists current via TvhSyncManager, TvhSyncWorker, EpgRepository, DvrRepository, IptvEpgSyncer, IptvEpgSyncWorker, and TifAllowlistSyncer.
  • Low-Friction Setup & LAN Curation: Support guided setup (TvhSetupFragment, IptvSetupWizardScreen) and LAN web curation (LanCurationServer, M3uCurationScreen).
  • Verifiable Quality & Releases: Maintain unit test coverage under app/src/test/ and release automation via .github/workflows/release.yml and GitHubUpdateManager.

3. In-Scope vs. Out-of-Scope & Guardrails

In Scope

Tvheadend HTSP Live & DVR

HTSP messaging, connection pooling, channel registry, repositories, and custom data/extractor/MP2 playback (htsp/, player/, sync/).

In Scope

IPTV M3U, XMLTV & TIF Sync

Streaming M3U/XMLTV parsers, stream scanning/resolution, logo and allowlist storage, and TIF channel/allowlist synchronization (iptv/).

In Scope

Android TV UI & Frame-Rate Matching

TV navigation, guide, recordings, search, player OSD/overlays, and display refresh-rate controller (ui/, player/afr/).

In Scope

LAN Browser Curation

Embedded LAN HTTP server and web asset for curating channels/playlists outside the TV remote (LanCurationServer.kt, assets/curation/index.html).

In Scope

Unit Testing & GitHub Release Updates

JVM unit tests under app/src/test/, release workflow (.github/workflows/release.yml), and in-app GitHub release/APK updater (updater/).

Out of Scope

Running a Tvheadend Server on Android

This repository is an Android TV client/TIF integration, not a replacement for the Tvheadend backend server itself.

Out of Scope

Unverified or Fabricated Specs

Claims about uninspected file contents, exact library versions, or external cloud backends not evidenced in the archive are excluded.

Out of Scope

Premature Split-App or HLD Lock

Reconciling split-app vs. combined-app direction (docs/SPLIT-APPS-FEASIBILITY.md) belongs to architectural resolution prior to locking hld.html, not Gate 02 framing.

Guardrail

LAN & Update Security Hygiene

Scope LanCurationServer exposure carefully on local networks, protect account/sync credentials, and validate APK install paths (ApkInstaller, file_paths.xml).

Guardrail

Streaming & Background Resilience

Use streaming parsers (StreamingM3uParser, StreamingXmltvParser), pooled reconnects, and background workers (TvhSyncWorker, IptvEpgSyncWorker) to avoid ANRs or OOMs.

Guardrail

Cross-Input TIF Isolation

Prevent collisions between TvheadendInputService and IptvTvInputService across TIF channel observers and allowlist syncers (see docs/TIF-CROSS-INPUT-AUDIT.md).

Guardrail

TV Ergonomics & Tune Observability

Keep D-pad navigation responsive, surface tune telemetry via TuneTelemetryTracker, and align with existing .arch-studio/ and docs/ artifacts.

4. Key Risks, Assumptions & Open Decisions

Assumptions & Technical Risks

  • Assumption (Archive Layout): The provided archive entry list reflects the repository structure of nmaclean/android-tvheadend-tif; file contents were not read in this pass.
  • Risk — TIF Cross-Input Collisions: Sharing TIF channels/observers across Tvheadend and IPTV inputs can cause duplicate entries, drift, or unintended overwrites if boundaries are loose.
  • Risk — Stream/Mux & Decoder Edge Cases: Unusual HTSP streams, MP2 audio, or server state changes can stall playback or disrupt AFR switching if error handling is incomplete.
  • Risk — Large Feeds & LAN Exposure: Oversized M3U/XMLTV feeds or an exposed LanCurationServer endpoint can strain memory/sync workers or local network boundaries.

Open Decisions Before UI Mockups & HLD

  • Combined vs. Split Input Architecture: Review docs/SPLIT-APPS-FEASIBILITY.md, docs/TIF-CROSS-INPUT-AUDIT.md, and docs/boundary-contract-audit.md alongside existing .arch-studio/vision.html and .arch-studio/hld.html.
  • Feature Maturity & Scope Lock: Inspect source files to confirm which Tvheadend, IPTV, AFR, curation, and updater paths are complete vs. in-progress.
  • Performance & Compatibility Targets: Confirm target Android / Android TV API levels in app/build.gradle.kts and concrete tune-time / sync budgets.
  • LAN Curation Access Model: Decide default lifecycle (on-demand vs. persistent) and local network access controls for LanCurationServer.
