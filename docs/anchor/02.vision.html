Vision: android-tvheadend-tif

Unified Android TV Input Framework (TIF), HTSP/Tvheadend live & DVR playback, and curated LAN IPTV/EPG experience built for 10ft living-room television control.

repo: nmaclean/android-tvheadend-tif remote: https://github.com/nmaclean/android-tvheadend-tif.git 130 indexed files role: Principal Software Architect

1. Executive Vision & Core Outcomes

North-Star Vision

Deliver a cohesive, ad-free 10ft Android TV application and TIF integration that bridges a local Tvheadend backend (HTSP, channels, EPG, DVR recordings) and LAN-curated IPTV sources into native Android TV surfaces—supporting D-pad navigation, automatic frame-rate matching (AFR), and local LAN autonomy without cloud lock-in.

Target Users

10ft Living-Room Viewers: Family members operating Android TV with a remote/D-pad across live TV, EPG timeline/grid, search, and DVR recordings.

Home-Media Self-Hosters: Administrators maintaining a LAN Tvheadend instance, M3U/XMLTV inputs, LAN curation server, and OTA/GitHub release updates.

Measurable Success Criteria

  1. Channel & Stream Tuning Reliability: End-to-end tuning via TvheadendInputService, IptvTvInputService, HtspClient / HtspConnectionPool, and HtspDataSource / HtspDvrDataSource / HtspExtractor (including Mp2Decoder and AFR session helpers) with structured telemetry tracked in TuneTelemetryTracker and PerfTrace.
  2. 10ft D-Pad & Surface Ergonomics: Full remote-driven navigation across MainActivity, TvPlayerActivity, DvrPlayerActivity, GuideScreen / ChannelGuideFragment / EpgTimelineOverlayFragment, RecordingsScreen, SearchScreen, and overlays (PlayerOsdOverlay, TrackSelectionOverlay, ProgramDetailsModal, TvhActionModal).
  3. Background Sync & Allowlist Integrity: Resilient synchronization across TvhSyncManager, TvhSyncWorker, EpgRepository, DvrRepository, InputChannelRepository, and IPTV pipelines (StreamingM3uParser, StreamingXmltvParser, IptvEpgSyncWorker, AllowlistRepository, TifAllowlistSyncer).
  4. LAN Curation & Self-Hosted Updates: Working LAN channel curation (LanCurationServer, LanNetworkUtils, M3uCurationActivity / M3uCurationScreen) and release verification via GitHubUpdateManager, ApkInstaller, and .github/workflows/release.yml.

2. System & Trust Boundaries Diagram

Boundaries separate on-device Android TV runtime components, local persistence/TIF providers, home LAN services (Tvheadend, M3U/XMLTV/logo hosts, curation clients), and external GitHub release endpoints.

3. In-Scope vs. Out-of-Scope & Guardrails

In Scope
Tvheadend HTSP Live TV & DVR Playback

Live channel tuning, recording playback, and stream extraction via HtspClient, HtspConnectionPool, HtspDataSource, HtspDvrDataSource, HtspExtractor, and Mp2Decoder.

In Scope
Android TIF Integration & Background Sync

Exposing Tvheadend and IPTV channels/EPG to Android TV via TvheadendInputService, IptvTvInputService, TifAllowlistSyncer, TifChannelObserver, and WorkManager sync workers.

In Scope
10ft TV Navigation, Guide, Search & AFR

Remote-friendly TV UI across MainActivity, TvPlayerActivity, DvrPlayerActivity, GuideScreen / ChannelGuideFragment, RecordingsScreen, SearchScreen, and DisplayFrameRateController.

In Scope
IPTV Ingestion, LAN Curation & APK Updates

Streaming M3U/XMLTV parsing, stream scanning, allowlist storage, LanCurationServer curation UI, and GitHub release checks via GitHubUpdateManager and ApkInstaller.

Out of Scope
Non-10ft Form Factors & Touch-First Apps

Phone/tablet touch-first clients, desktop UIs, or watch apps are outside this 10ft Android TV / TIF codebase (aside from browser access to LanCurationServer on the LAN).

Out of Scope
Cloud-Hosted Multi-Tenant Media Backends

External cloud TV relays, commercial streaming accounts, or centralized user-account services beyond TvhAccountService and GitHub release endpoints are not part of the target architecture.

Out of Scope
Running Tvheadend Server & Tuner Hardware

Hosting Tvheadend itself, wiring DVB-T2/IPTV tuners, or managing homelab infrastructure (such as Ubuntu Docker stacks or Home Assistant) is external to this Android app.

Out of Scope
Implementing Code in Gate 02

Editing Kotlin sources, altering tasks.md execution state, or locking UI wireframes/HLD contracts before Gate 02 vision and boundary sign-off.

Guardrail
Streaming & Bounded Memory on TV Hardware

Use streaming parsers (StreamingM3uParser, StreamingXmltvParser) and connection pooling (HtspConnectionPool) so large playlists, EPG feeds, and live streams do not exhaust TV memory.

Guardrail
LAN Resilience & Explicit Error/Telemetry States

Handle connection state changes (HtspConnectionState), stream stalls (tested in HtspDataSourceStallTest), and tune stages (TuneTelemetryTracker) without freezing the 10ft UI.

Guardrail
Network & Input Validation Boundaries

Validate setup inputs (TvhSetupInputValidator), scope LanCurationServer to local network usage (LanNetworkUtils), and treat external M3U/XMLTV/GitHub responses as untrusted.

Guardrail
Testability & Release Gate Discipline

Keep protocol, parser, sync, state reducer, and UI state logic covered by unit tests under app/src/test/java/com/nmaclean/tvheadend/ and aligned with .github/workflows/release.yml.

4. Key Risks, Assumptions & Open Decisions

Assumptions

  • Repository Grounding: The indexed repository at /workspace/android-tvheadend-tif (https://github.com/nmaclean/android-tvheadend-tif.git) contains the active Kotlin Android TV / TIF codebase and existing tests.
  • Coexistence of Legacy & Compose/Leanback Surfaces: Both classic Leanback/Fragment screens (such as ChannelGuideFragment, HomeFragment, TvhSetupFragment, IptvSetupFragment) and Compose/Activity screens (such as MainActivity, GuideScreen, LiveTvScreen, RecordingsScreen, SearchScreen, IptvSetupWizardScreen) exist in the repository and must remain consistent.

Key Risks & Failure Modes

Dual UI / Sync Paths Causing State Drift

Parallel UI flows (Leanback fragments vs. Compose screens, plus Tvheadend HTSP vs. IPTV allowlist/EPG sync) can diverge in channel state, playback strategy, or TIF channel registration if boundaries are not explicitly mapped in HLD.

LAN Stream Stalls, Codec Mismatches & Tuner Contention

Live TV and DVR playback over LAN can stall or fail due to HTSP socket drops, MPEG-2/MP2 codec handling (Mp2Decoder), or display mode switches (DisplayFrameRateController).

LAN Curation Server & External Feed Exposure

Running an embedded LAN server (LanCurationServer) and fetching external M3U/XMLTV/GitHub release metadata requires careful network binding and parsing safeguards.

Open Decisions Before UI Mockups & HLD

1. Canonical Primary 10ft UI Stack

Confirm whether Compose screens (MainActivity, GuideScreen, LiveTvScreen, RecordingsScreen, SearchScreen) or Leanback fragments are the primary 10ft experience going forward, and how legacy activities/fragments are maintained.

2. Unified vs. Separated Playback & Sync Contracts

Clarify how InputPlaybackStrategy, InputPlaybackPolicy, BackgroundSyncStrategy, and InputChannelRepository coordinate Tvheadend HTSP vs. IPTV sources in TIF.

3. Release & Self-Update Governance

Confirm how .github/workflows/release.yml artifacts align with in-app GitHubUpdateManager / ApkInstaller checks and whether any signing or LAN-only distribution constraints apply.
