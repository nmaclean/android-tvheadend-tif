02 Ordered Epics (E1–E6)

Epics are sequenced from foundational platform/connection wiring to channel/EPG sync, playback, user configuration/diagnostics, and operational hardening.

E1
Android TIF Service & Project Foundation
Dependencies: None (Entry Epic)
High-Level Scope & Outcomes

Establish the Android TV application module, build configuration, permissions, TvInputService declaration, and baseline reverse-engineered inventory of existing repository components.

Rationale & Boundary

Android requires a registered TvInputService and manifest metadata to participate in TIF. Bounding this first isolates platform wiring and existing code audit from protocol and UI work.

Existing vs. Gap / Assumption
  • Inferred: Repo contains a baseline Android TIF project skeleton or partial service implementation.
  • Gap/Assumption: Target SDK, Kotlin/Java baseline, and current build health are unverified without build/manifest files.
E2
Tvheadend Server Connectivity & Session Layer
Dependencies: E1
High-Level Scope & Outcomes

Manage connection lifecycle, endpoint configuration, credentials/authentication, reachability checks, and streaming profile selection against the Tvheadend server.

Rationale & Boundary

Both EPG/channel metadata and media streams depend on a reachable, authenticated Tvheadend connection. Keeping transport/auth separate from TvContract prevents network concerns from leaking into Android content provider logic.

Existing vs. Gap / Assumption
  • Inferred: A client/connector layer communicates with a Tvheadend instance over network APIs or streams.
  • Gap/Assumption: Protocol choice (HTSP vs. HTTP API), auth handling, and multi-server/profile support require source verification.
E3
Channel Lineup & EPG Metadata Synchronization
Dependencies: E1, E2
High-Level Scope & Outcomes

Map Tvheadend channels, channel tags/groups, logos, and program guide entries into Android's TvContract tables, handling incremental updates, stale pruning, and scheduled/background refreshes.

Rationale & Boundary

Channel and program ingestion has distinct data mapping, idempotency, and scheduling rules from live video decoding, making it a clean domain boundary.

Existing vs. Gap / Assumption
  • Inferred: Channels and program guide data are pushed or synced into Android TV's TvContract provider.
  • Gap/Assumption: Sync frequency, incremental diffing vs. full refresh, and artwork/logo handling are unconfirmed.
E4
TIF Session Media Playback & Stream Control
Dependencies: E1, E2, E3
High-Level Scope & Outcomes

Implement TvInputService.Session tune/release/surface binding, stream URI or socket resolution, audio/video track selection, and error/rebuffer handling for live TV tuning.

Rationale & Boundary

Live tuning has strict real-time surface, audio focus, and state-transition constraints in Android TIF that should be isolated from metadata batch sync.

Existing vs. Gap / Assumption
  • Inferred: At least a basic session/player path tunes a selected channel stream onto a TIF surface.
  • Gap/Assumption: Supported codecs/containers, timeshift/seek behavior, and tuner-busy error handling are unknown.
E5

Rationale & Boundary

Configuration and troubleshooting workflows serve administrators/viewers outside active playback sessions and should evolve cleanly without coupling UI states to background sync workers.

Existing vs. Gap / Assumption
  • Verified Context: Gate 03 (mockup-concept.html) and Gate 04 (hld.html) exist in prior context.
  • Gap/Assumption: Only partial CSS/header snippets of Gates 03–04 were present, and current Android settings/setup UI coverage in the repo is unverified.
